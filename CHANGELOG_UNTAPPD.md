# v74 transport notes

- Adds a manual live smoke probe above the existing v73 self-healing transport.
- Production smoke performs only a tiny serial workload and does not alter transport authority or matching semantics.
- No scheduled GitHub smoke automation is used.

# v73 transport hardening

- A non-429 authoritative browser-fetch error now invalidates the cached search template instead of allowing a stale request shape to cascade through the remainder of the batch.
- The affected query receives exactly one UI-driven recovery attempt. A successful UI request becomes the new template for later direct searches.
- Recovery is bounded: persistent failure returns normally through the existing failed-result path; there is no retry loop.
- Direct HTTP 429 remains fail-fast and is not retried through the UI.
- Adds recovery/invalidation counters to the transport timing summary.
- Adds typed Algolia request and transport-event contracts for static checking.

# v72 transport authority

The first successful UI search captures the exact Algolia request shape. Subsequent primary and fallback page-0 searches reuse that request serially through browser-context `fetch()`. A direct HTTP 429 is surfaced immediately and is not retried through the UI. Expansion/sorted-page replay remains unchanged.

# v71

- Adds bounded exact browser-context replay of captured page-0 Algolia search requests for parity measurement.
- Adds parity/error/rate-limit/timing counters.
- Shadow mode is serial and opt-in; it never retries and never supplies data to the matcher.

# Untappd transport changelog

## v59

- No Untappd transport behavior changes. v59 only extracts batch/CSV/resume responsibilities from `untap.py`.

## v58

- Introduced `untap_untappd.py` as the dedicated browser/network transport layer.
- Extracted the existing validated Playwright lifecycle, Untappd search submission, captured request/response handling, Algolia request parsing and browser-context replay, ABV-sort replay, DOM diagnostics/result retrieval, beer detail-page extraction, HTTP/network status helpers, and Algolia request counters.
- Playwright import is deliberately lazy so parser/preflight-only commands stay browser-free.
- The extraction is intended to preserve the exact v57 request sequence and network behavior; it introduces no new retries, backoff, queries, expansion rules, or rate-limit handling.

## v58 live-validation correction

- Added the missing `re` import in `untap_untappd.py`. The transport extraction moved `extract_beer_info()` into this module, but its regular-expression dependency was not moved with it. This caused every otherwise-confirmed detail extraction to fail with `name 're' is not defined`.
- Added a transport regression test that exercises detail-page text parsing so this class of extraction/import error is caught without a live Untappd run.

## v60

- No browser, Algolia, request-count, replay, detail-extraction, or HTTP-429 behavior changes.
- Removed an unused parser-helper import.
- Added architecture-contract coverage preserving the lazy Playwright import boundary and dependency direction.

## v61

- Replaced the transport module's four fixed Playwright sleeps with bounded condition-based waits.
- Normal and fallback search submission now waits for the exact Algolia response whose decoded request query matches the submitted query.
- The ABV-sort diagnostic waits on the exact Algolia response generated by both the baseline search and sort selection.
- Detail extraction waits for a visible `h1` rather than sleeping for a fixed one-second interval, while preserving tolerant extraction if the heading never appears.
- Added regression coverage ensuring `untap_untappd.py` contains no `page.wait_for_timeout(` calls and that the query-specific response predicate is enforced.
- No retry/backoff behavior was added; a missing expected search response now fails via the existing batch exception path after a bounded timeout instead of reading potentially stale DOM after an arbitrary delay.

## v62

- The known-good Playwright runtime is now pinned to `playwright==1.57.0` at the release/environment level.
- CI installs the corresponding Chromium bundle but does not make live Untappd requests.

### v68 validation patch
- `submit_search()` now arms the exact-query Algolia response listener before the entire UI submit action (`fill` + `Enter`).
- This closes a live-search timing race where Untappd could send the Algolia request during `fill`, ahead of the old listener window, producing a false 10-second timeout.
- Request count and response-correlation semantics are unchanged.
